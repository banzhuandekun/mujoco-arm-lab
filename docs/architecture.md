# 架构说明

## 设计目标

这个仓库首先是一个可复现的控制实验，不是生产机器人控制栈。架构围绕三个目标：

1. 核心控制与评测只保留一份实现；
2. 演示、失败实验和正式评测从目录上就能分清；
3. 每条命令行入口都能从仓库根目录直接运行，模型和输出路径不随脚本位置变化。

## 目录职责

| 位置 | 职责 | 是否应放业务逻辑 |
|---|---|---|
| `src/mujoco_arm_lab/` | 可复用控制、环境、策略和评测代码 | 是 |
| `scripts/` | 学习路线中的演示与训练入口 | 只放参数解析和终端输出 |
| `experiments/` | 特定实验，包括未收敛 RL 与避障矩阵 | 可以放实验编排 |
| `tools/` | 与算法无关的资产转换工具 | 否 |
| `tests/` | 行为、几何和指标口径测试 | 否 |
| `models/` | MJCF 场景资产 | 否 |
| `outputs/` | 视频、图片和训练权重 | 否 |
| `docs/` | 架构、评测口径和入口索引 | 否 |

## 模块依赖

依赖方向保持单向，避免包内循环导入：

```text
scripts / experiments / tools
              |
              v
       mujoco_arm_lab
   +----------+----------+
   |          |          |
control    obstacle   env / bc
   |          |
   |          +----> evaluation
   |
   +----> paths

obstacle -> avoidance -> matrix
```

主要模块：

- `control.py`：模型加载、随机目标采样、DLS-IK 和基础 `Reacher`。
- `obstacle.py`：在基础控制器上增加障碍物配置和接触检测。
- `avoidance.py`：安全关节构型、肘部上抬解析逆解和避障执行器。
- `matrix.py`：固定目标点下的位置 × 半径评测编排。
- `evaluation.py`：单轮记录格式和所有汇总指标的唯一定义。
- `env.py`：把同一控制场景包装成 Gymnasium 环境。
- `bc.py`：行为克隆网络及推理接口。
- `paths.py`：从包文件位置反推仓库根目录，集中管理模型和输出路径。

## 运行数据流

普通 DLS-IK 一次尝试：

1. `sample_target()` 生成世界坐标目标；
2. `Reacher.reset()` 恢复初始关节角并摆放目标球；
3. 每 5 个仿真步执行一次 `ik_step()`；
4. MuJoCo 位置执行器跟踪关节目标；
5. 末端进入 5 mm 阈值或达到 4000 步时结束。

避障尝试在此基础上增加安全关节姿态和肘部上抬解析解，但最终仍用同一套 DLS-IK
完成收敛。因此两种方法可以在同一批目标点、同一时间预算下比较。

## 扩展约定

新增控制器时遵守以下顺序：

1. 优先继承或组合 `Reacher`，不要复制模型加载、雅可比计算和到达判定；
2. 通过 `make_episode()` 和 `summarize_episodes()` 生成指标；
3. 入口脚本只负责参数解析、调用实验函数和格式化终端输出；
4. 至少增加一个正常路径测试和一个边界条件测试；
5. 如果改变评测口径，同步更新 `docs/evaluation.md` 和 README 中的历史结果说明。

当前避障策略只适用于位置已知的右前方低位静态单球。不要把这段代码描述成通用
运动规划器；其他位置的失败结果已经记录在 README 中。
